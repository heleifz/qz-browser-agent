## 1. 为什么要做 v0.3

v0.2.5 首轮基线（Grok 4.7）首跑 **29/30 = 96.7%**，自建 19 题全部通过，大多 10–30 秒就跑完。题目已经测不出能力差距了。用户的反馈是"开源的都过于简单了"。

基线里暴露的真问题有这几类：
1. **过度执行**：arxiv 题把 2,383 篇论文全抓了一遍，用了 527 秒；GitHub--29 调了 41 次工具。
2. **截图循环导致上下文溢出**：AHR 题就是这么失败的，也是本轮唯一的失败。
3. **判分太松**：有歧义（SmartAsset）、有漂移（HGX）、有措辞模糊（arxiv）、有跳登录（GitHub pricing）。
4. **成本看不清**：现在只能拿到每个会话最后一次 LLM 调用的 usage。

v0.3 的目标是**拉开区分度、测出效率问题、让判分可复现**。v0.2.5 原样保留，降级为回归/冒烟集，不再计入能力分。

## 5. 判分怎么收紧

1. **固定输出格式**：每题末尾要输出一行 `key=value; ...`，rule 只匹配这一行里的值。这样不会因为"答案里提过这个数"就误判通过。
2. **judge.py 新增的判分键**（已实现，已用合成答案和 v0.2.5 基线回归测过，旧题的判定结果完全不变）：
   - `any_of`：每组至少命中一个（用来容忍拼写和口径差异，比如 Hänsch/Hansch，Ubuntu 的 2027-04 到 06）；
   - `must_not_include`：陷阱值命中直接判失败（比如 `spec_pep=622`、`choice=Node 22`、`obsoletes_two=HTTP/3`）；
   - `must_match`：正则（判时间敏感题的格式和域名）；
   - `numbers_near`：数值容差（arxiv 总数 ±3%）；
   - 归一化：去掉 `$`、千分位逗号、markdown `**`/反引号，统一列表逗号后的空格。
3. **必须字段**：每题 `must_include` 里列的就是必须字段。表格题另加 `min_rows`。
4. **时间漂移的处理**：
   - 优先选历史区间或已经冻结的数据（ECB 历史汇率、USGS 2023 地震目录、PyPI 2023–24 版本、已 EOL 的 Python 3.10）；
   - 会变的部分只判格式，数值交给人工抽查（`review` 字段会自动进入 `review_queue.md`）；
   - 会随日期翻转的答案用 `any_of` 把两种都接受（Node 24/26）。
5. **防止过度执行的软预算**：每题都有 `budget`（`max_tool_calls` / `max_elapsed_s` / `max_screenshots`）。judge 会算出 `efficiency`（工具调用、截图、run_script、compact、耗时）和 `over_budget`。**预算不影响 pass/fail**，scoreboard 另外报 `pass_within_budget`，相当于"pass@budget"。题面里也写明了"不要全量打印""不要逐个打开"。
6. **Skill 判定加严**：
   - runner 把 Skill 两段式题串行执行（全局锁），并发时 `skills list` 的差集就不会混进别的题的 Skill；
   - judge 不再接受"恰好新增了一个不相关的 Skill"这种兜底，只认同名、同前缀，或者 create_skill 参数里带了本题前缀的情况。

## 6. 累计 token 和成本统计方案

**现状**：qz CLI 的 `show` 只暴露最后一次调用的 `contextUsage`，所以基线成本只能给一个区间（$0.94–$21）。

**方案 A（已写进 runner，默认关闭，还没实跑）**：`run_eval.py --usage-poll 5`
- 用 `create`（不加 `--wait`）拿到 session id，前台 `watch`，后台每 5 秒 `show` 一次；
- 把去重后的 contextUsage 样本累加，得到 `usage_cum.cost_usd_lower`。这是累计成本的下界，两次轮询之间的调用会漏掉；
- 再用 `最后一次调用成本 × LLM 轮次`（assistant + tool 条目数）算出 `cost_usd_upper_est`；
- judge 汇总到 `scoreboard.cost`：`cost_usd_last_calls_sum`、`cost_usd_cum_lower_sum`、`cost_usd_cum_upper_est_sum`、`tool_calls_sum`、`screenshots_sum`、`compacts_sum`。

**方案 B（无侵入，已实现）**：judge 从 transcript 统计工具调用、截图、compact 和 transcript 字符数，作为成本代理指标。对基线回放的结果：462 次工具调用、11 张截图、7 次 compact，末次调用成本合计 $0.938。

**方案 C（需要研发，没有提）**：让 qz 在 `show` 里返回会话级累计 usage（或者每轮 usage 数组）。这是最准确的口径，但属于研发需求，要用户同意后才能提。

在 C 落地之前，正式报告里的成本一律写成"下界–上界"区间，并注明采样间隔。

## 7. 风险与不可达站点

- **box 出口不可达（已避开）**：fred.stlouisfed.org 和 uitestingplayground.com 超时；bls.gov、census.gov、cdc.gov、sec.gov、congress.gov、timeanddate.com、npmjs.com 返回 403；metmuseum.org 返回 429；crates.io（SPA）用 curl 拿到 404。
- **SPA 无法用 curl 验金标**：demoqa 的 modal 格式（`15 March,1990`、`Haryana Panipat`）是按应用的已知行为写的，首跑时要人工确认一次。
- **Wikipedia 可编辑**：导师链题跑前要用 API 复核 4 个 infobox。
- **默认值会变**：两个房贷计算器的默认税费会变，所以 `total_*` 不进 gate。SmartAsset 的税表按年更新。
- **会随日期翻转的题**：Node LTS 题在 2026-10-28 之后 Node 26 也算对，rule 已兼容；`compare-lifecycle-3stack` 的 already_eol 到 2027 年会扩大，届时要改金标。
- **轮询采样**：`--usage-poll` 是新代码路径，没有对真实浏览器跑过；它依赖 `create` 不加 `--wait` 时返回 session id。如果字段名不同，代码会退化为 `status=error`，需要首跑时验证。
- **难度预期**：本版预计首跑通过率明显低于 96.7%（目标区间 50–75%，用来拉开区分度），成本也会上升。单题超时 600–900s，建议先挑 5 题抽样试跑，再决定是否全量。

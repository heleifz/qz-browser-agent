## Token 与成本估算

- qz CLI 只暴露每个会话**最后一次** LLM 调用的 `contextUsage`（prompt/completion tokens、`cost_in_usd_ticks`，1 USD = 1e10 ticks），没有累计值，所以只能给区间：
  - 首跑：下界 **$0.938**（各会话末次调用之和）；粗略上界 **$21.33**（末次调用成本 × 轮数，明显高估：上下文逐轮增长且大量缓存命中）。
  - 重跑：下界 $0.031，上界 $0.9。
- 末次调用上下文：自建题多在 27–45k；Skill 两段合计 65–79k；OM2W/WV 真实站 44–98k，最高 nvidia 98k、arxiv 94k，离 112k 溢出线不远。

## 观察（只记录，未改题、未提研发）

1. **天花板效应**：自建 19 题全过、多数 10–30s 完成，区分度不足；真实站（OM2W/WV）才拉开耗时与上下文差距。后续版本需要更难的自建题，或提高真实站占比。
2. **过度执行**：arxiv 题只需完成筛选搜索，agent 把 2,383 篇全部抓进数据表（527s、上下文约 94k）；GitHub--29 读了 41 次工具（170s）。结果对，但成本和时间偏高。
3. **截图完美主义 → 溢出**：AHR 题首跑卡在反复截图、隐藏遮挡元素的循环；同一会话里多张截图 + 脚本输出把上下文顶满。
4. **题目问题记录**：
   - `om2w:bc2ce7…`（SmartAsset）题面说 *taxable income* $158,500，计算器按 household income 再扣标准扣除，得 $27,107；如按应税所得直接算约 $30,887。判分说明只要求「填计算器、报显示值」，本轮判 pass，题面存在歧义。
   - `om2w:b4aa73…`（HGX 驱动）金标版本随时间漂移（v0.2.5 试跑 595.112.07 → 本轮 615.71.10，已复核 release notes 发布日 2026-10-19）；agent 没走 en-us/drivers 搜索器而是经 docs/CUDA repo 到达，判分说明未限定路径。
   - `om2w:71f8de…`（arxiv）判分说明写「report top results」，agent 只给总数 + 数据表名，未在答案里列 top 条目；本轮按任务主体判 pass，标准偏模糊。
   - `wv:GitHub--29`：github.com/pricing 在评测环境重定向到登录页，agent 改用 docs + web.archive 快照；结论正确，但题目原意的数据源已不可直达。
5. **评测器口径**：并发 3 时，Skill 题 create 阶段的 `skills_new_or_updated` 会混入同批其他 Skill 题新建的 `qzb-*`（如 `skill-login-check` 看到 3 个）；judge 以精确名匹配判定，本轮不受影响，但 `create_note` 的兜底分支在并发下可能误判。
6. **成本可观测性**：缺累计 token/成本，基线成本只能给区间。
